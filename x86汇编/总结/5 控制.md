### 核心总结

程序默认是按顺序一行一行执行的。为了实现 `if`、`else`、循环和 `switch` 等逻辑，CPU 需要有能力**改变执行顺序**。

这份文档讲解了实现这一点的“三部曲”：

1.  **设置条件（提问）**：CPU 执行算术或逻辑运算后，会根据结果（如“是否为零？”、“是否为负？”）设置一组特殊的 1 位寄存器，称为**条件码 (Condition Codes)**。
2.  **读取条件（回答）**：使用 `SET` 指令将条件码的组合（如“是否小于？”）转为一个 `0` (false) 或 `1` (true) 的字节值。
3.  **执行跳转（行动）**：使用**跳转 (Jump)** 指令，根据条件码的状态（如“如果相等就跳转”）来**改变下一条要执行的指令的地址**，从而跳过代码块或重复执行代码块。

此外，文档还介绍了两种实现 `if` 逻辑的策略：
* **传统方式**：使用**条件跳转 (JUMP)**。
* **现代方式**：使用**条件传送 (CMOV)**，以避免分支预测失败带来的巨大性能惩罚。

最后，文档深入探讨了 `while`、`for` 循环的实现模式，以及 `switch` 语句如何使用高效的**跳转表 (Jump Table)** 来实现。

### 关键知识点讲解

#### 1. 条件码 (Condition Codes)

CPU 有一组 1 位的标志寄存器，用于描述最近一次算术/逻辑操作的结果。最重要的四个是：

* **`ZF` (Zero Flag)**：结果是否为 **0**？
* **`SF` (Sign Flag)**：结果是否为**负数**？
* **`CF` (Carry Flag)**：**无符号**运算是否溢出？
* **`OF` (Overflow Flag)**：**有符号**运算是否溢出？

**注意**：`leaq` 指令**不改变**任何条件码。

#### 2. `CMP` 和 `TEST`：只提问不操作

大多数指令（如 `ADD`, `SUB`）会“顺带”设置条件码。但 `CMP` 和 `TEST` 的**唯一**工作就是设置条件码，而不改变任何数据寄存器。

* `CMP S1, S2`：
    * **作用**：计算 `S2 - S1`，并根据结果设置条件码。
    * **用途**：比较两个数。例如，如果 `S1 == S2`，结果为 0，`ZF` 标志就会被置为 1。
* `TEST S1, S2`：
    * **作用**：计算 `S1 & S2`（按位与），并根据结果设置条件码。
    * **用途**：`testq %rax, %rax` 是检查 `%rax` 是否为 0 的最高效方式。

#### 3. 如何使用条件码

文档介绍了三种使用条件码的方法：

##### 方法 1：`SET` 指令 (实现 `bool`)

* **作用**：根据条件码（如 `setl` - "Set if Less"）将一个 1 字节的目的寄存器（如 `%al`）设置为 `0` 或 `1`。
* **典型模式 (C 语言 `bool result = a > b;`)**：
    1.  `cmpq %rsi, %rdi`：提问（比较 `a` 和 `b`）。
    2.  `setg %al`：回答（如果“大于(Greater)”，则 `%al` = 1，否则 = 0）。
    3.  `movzbl %al, %eax`：格式化（将 1 字节的 `%al` 零扩展为 32 位的 `0` 或 `1`，存入 `%eax` 作为函数返回值）。

##### 方法 2：`JMP` 指令 (实现 `if/else/loop`)

* **作用**：改变程序的执行流程。
* `jmp .L1`：**无条件**跳转到标号 `.L1`。
* `je .L1` (Jump if Equal), `jl` (Jump if Less) 等：**有条件**跳转。
* **PC 相对寻址（重要）**：跳转指令存储的不是目标的绝对地址，而是目标地址与**下一条指令地址**之间的**偏移量**。这使得代码可以被加载到内存的任意位置而无需修改，称为**位置无关代码**。

##### 方法 3：`CMOV` 指令 (实现高性能 `if`)

* **作用**：`cmovge S, R` (Conditional Move if Greater or Equal)。只有当条件满足时，才将源 `S` 的数据复制到目的寄存器 `R`。
* **C 语言 `result = (x < y) ? (y - x) : (x - y);` 的 `CMOV` 编译**：
    1.  `movq %rsi, %rax`：`%rax = y`
    2.  `subq %rdi, %rax`：`%rax = y - x` (计算 `then` 块的结果 `rval`)
    3.  `movq %rdi, %rdx`：`%rdx = x`
    4.  `subq %rsi, %rdx`：`%rdx = x - y` (计算 `else` 块的结果 `eval`)
    5.  `cmpq %rsi, %rdi`：比较 `x` 和 `y`
    6.  `cmovge %rdx, %rax`：**关键！** 如果 `x >= y` (ge)，则 `rval = eval`（即 `%rax = %rdx`）。
    7.  `ret`：返回 `%rax`。

* **为什么用 `CMOV`？（性能）**
    * 现代 CPU 使用**流水线 (pipelining)**。
    * 遇到**条件跳转 (JMP)** 时，CPU 必须**猜测 (Branch Prediction)** 走哪条路。
    * **猜错的代价极大**：CPU 必须丢弃流水线中所有已做的工作，重新加载正确的指令，浪费 15-30 个时钟周期。
    * `CMOV` **没有跳转**，它总是顺序执行。虽然它计算了两个分支，但这个代价远小于一次分支预测错误的代价。
* **`CMOV` 的局限性**：
    * `CMOV` 会**执行两个分支的所有计算**。
    * 如果分支有**副作用**（如 `cnt++`）或**潜在错误**（如解引用空指针 `*xp`），则**不能**使用 `CMOV`，否则会导致程序崩溃或逻辑错误。

#### 4. 循环 (Loops)

循环就是用 `CMP` 和 `JMP` 实现的。

* **`do-while`**：最简单的。代码块在后，测试和跳转在尾部 (`cmpq ... jg .L2`)。
* **`while`**：必须在循环体之前进行测试。有两种实现方法：
    1.  **跳转到中间 (Jump to Middle)**：先无条件 `jmp` 到循环尾部的测试，测试通过后再 `jmp` 回循环体的开头。
    2.  **Guarded-do**：在循环开始前先做一次**相反**的测试（`if (!t) goto done;`），如果通过，则进入一个标准的 `do-while` 循环。
* **`for`**：C 语言的 `for` 循环会被编译器转换成等价的 `while` 循环，然后按 `while` 的模式进行编译。

#### 5. `switch` 语句和跳转表

`switch` 可以实现**多路分支**。如果用一长串 `if-else` 来实现，会非常低效。

* **跳转表 (Jump Table)**：编译器会创建一个**数组**，数组的每个元素是 `case` 对应的**代码块地址**。
* **`switch` 的执行过程**：
    1.  **计算索引**：`index = n - 100`（`100` 是 `case` 的最小值）。
    2.  **边界检查**：`if (index > 6)`（`6` 是最大范围），如果超出，则 `jmp` 到 `default` 块。
    3.  **查表**：从跳转表 `.L4` 中获取地址。`jmp *.L4(,%rsi,8)`，意思是：
        * `.L4`：表的基地址。
        * `%rsi`：索引 `index`。
        * `8`：比例因子（因为每个地址占 8 字节）。
    4.  **间接跳转**：`jmp` 到从表中取出的地址。

* **优点**：执行时间与 `case` 的数量无关，非常快。
* **处理技巧**：
    * **Fall-through (case 102)**：在 `case 102` 的代码块 (`.L5`) 结尾**不写** `jmp`，执行就会自动“落入” `case 103` (`.L6`)。
    * **重复情况 (case 104, 106)**：让跳转表中索引 `4` 和 `6` 都指向同一个标号 (`.L7`)。
    * **缺失情况 (case 101, 105)**：让跳转表中索引 `1` 和 `5` 都指向 `default` 标号 (`.L8`)。

#### 6. 案例分析：教科书 vs 真实编译器

文档最后的案例分析（`switch_eg`）对比了教科书中的跳转表和真实编译器（`objdump`）生成的跳转表。

* **教科书版本**：简单直接。跳转表里存的是 8 字节的**绝对地址**。
* **真实编译器版本**：更复杂，但更优越（**位置无关代码, PIC**）。
    1.  跳转表里存的是 4 字节的**相对偏移量**（相对于表基址）。
    2.  执行时，CPU 动态计算最终地址：
        * `lea 0x0(%rip),%rcx`：获取跳转表的**基地址**。
        * `movslq (%rcx,%rsi,4),%rax`：从表里查出 4 字节的**偏移量**。
        * `add %rcx,%rax`：计算 `最终地址 = 基地址 + 偏移量`。
        * `jmp *%rax`：跳转到该地址。

这种“基址 + 偏移量”的模式是现代编译器和操作系统的基石，它允许代码（如共享库）被加载到内存的任何位置。
