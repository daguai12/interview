### 第一部分：核心概念——什么是 Promise 对象？

当您在函数中写下 `co_await`, `co_yield` 或 `co_return` 时，编译器就不再把它当作普通函数，而是编译成一个**协程**。

这个过程的核心，就是编译器会为您自动创建一个**Promise 对象**。

**请忘记 `std::promise`**：文档开篇就强调，不要把它和 `std::future/promise` 混淆。C++ 协程的 Promise 更应该被理解为一个\*\*“协程状态控制器” (Coroutine State Controller)\*\* 或\*\*“协程行为定制器”\*\*。

它的职责是：**在协程生命周期的各个关键节点，通过一系列预定义的方法，告诉编译器“接下来该怎么做”。**

这个 Promise 对象被创建在**协程帧 (coroutine frame)** 内部，与协程共存亡。

#### 编译器眼中的协程结构

文档给出的这个伪代码是理解所有后续内容的基础。您写的协程代码 `<body-statements>`，会被编译器自动包裹成类似下面的结构：

```cpp
{
  // 1. 初始挂起：决定协程是立即执行还是延迟执行
  co_await promise.initial_suspend();
  try
  {
    // 2. 您的代码在这里执行
    <body-statements>
  }
  catch (...)
  {
    // 3. 异常处理：如果您的代码抛出未捕获的异常
    promise.unhandled_exception();
  }
FinalSuspend:
  // 4. 最终挂起：协程执行完毕或异常处理后，进入最终状态
  co_await promise.final_suspend();
}
```

协程的整个生命周期，就是围绕着 Promise 对象的这几个关键方法调用展开的。

### 第二部分：协程的完整生命周期详解

文档详细拆解了从协程被调用到销毁的每一个步骤。我们来逐一分析：

#### 阶段一：协程的“诞生”——调用时发生了什么？

当你调用一个协程函数时，后台发生了一系列复杂操作：

1.  **分配协程帧**：

      * 编译器计算出需要多大内存来存放协程的所有状态（参数、局部变量、Promise 对象、管理信息等），然后调用 `operator new` 在**堆**上分配这块内存。
      * **重要优化**：如果编译器能确定协程的生命周期不会超过其调用者（例如，协程在调用函数返回前就执行完了），它可以直接在调用者的**栈**上分配协程帧，避免堆分配开销。
      * **`noexcept` 警告**：因为堆分配可能失败并抛出 `std::bad_alloc`，所以协程函数**通常不应被声明为 `noexcept`**。

2.  **拷贝参数**：

      * 函数的参数被拷贝或移动到刚刚分配的协程帧里。这是为了确保即使协程挂起，调用者的栈帧销毁后，这些参数依然有效。
      * **巨大陷阱**：如果是引用传递，只会拷贝引用本身，而不是它指向的对象。如果引用的对象在协程挂起期间被销毁，就会产生**悬空引用 (dangling reference)**。在协程中应极度小心使用引用参数。

3.  **构造 Promise 对象**：

      * 在协程帧内部，Promise 对象被构造出来。编译器会优先选择能接受所有协程参数的构造函数，如果找不到，就用默认构造函数。这让 Promise 有机会在构造时就“看到”协程的参数。

4.  **获取返回对象 (`get_return_object`)**：

      * 这是协程与调用者沟通的**第一个关键步骤**。编译器调用 `promise.get_return_object()`。
      * 这个方法返回一个对象，该对象最终会**返回给协程的调用者**。这个对象通常是一个 RAII 类型，它持有着协程的句柄，负责管理协程的生命周期。
      * **关键时序**：**必须在协程开始执行前获取返回对象**。文档解释了原因：如果协程 `resume()` 后立即就执行完并销毁了自己，那么之后再想从 promise 获取返回对象就会访问无效内存，导致崩溃。这个设计从根本上避免了竞态条件。

5.  **初始挂起 (`initial_suspend`)**：

      * 编译器执行 `co_await promise.initial_suspend()`。
      * 这是 Promise 控制协程启动行为的地方：
          * 如果 `initial_suspend` 返回一个**立即恢复**的 Awaitable (如 `std::suspend_never`)，协程会无缝地继续执行用户代码，这叫“热启动”或“立即启动”。
          * 如果返回一个**总是挂起**的 Awaitable (如 `std::suspend_always`)，协程会在此处挂起，将控制权和 `get_return_object` 返回的对象交还给调用者。之后需要调用者手动 `.resume()` 来启动协程，这叫“冷启动”或“延迟启动”。

#### 阶段二：协程的“终结”——返回、异常与销毁

1.  **正常返回 (`co_return`)**：

      * `co_return;` 被翻译为 `promise.return_void();`。
      * `co_return <expr>;` 被翻译为 `promise.return_value(<expr>);`。
      * 执行完上述调用后，程序会销毁所有局部变量，然后**跳转**到 `FinalSuspend` 标签处。

2.  **异常退出**：

      * 如果协程体内的代码抛出未被捕获的异常，会被 `try-catch` 块捕获。
      * 在 `catch` 块内，`promise.unhandled_exception()` 被调用。通常，Promise 会在这里捕获异常（通过 `std::current_exception()`）并保存起来，以便将来在合适的时机重新抛出。
      * 处理完异常后，同样会**跳转**到 `FinalSuspend` 标签处。

3.  **最终挂起 (`final_suspend`)**：

      * 这是协程销毁前的**最后一道关卡**。程序会执行 `co_await promise.final_suspend()`。
      * 它的作用是让协程在清理完所有资源后，决定是**立即销毁**还是**再挂起一次**。
      * **为什么建议总是挂起？** 文档指出，如果 `final_suspend` 总是挂起，协程的销毁就必须由外部（通常是 `get_return_object` 返回的那个 RAII 对象）调用 `.destroy()` 来完成。这使得协程的生命周期变得明确可控，编译器更容易进行优化（如栈分配）。
      * **重要规则**：处于最终挂起点的协程，**不能被 `resume()`**，只能被 `destroy()`。

4.  **销毁协程帧**：

      * 当 `.destroy()` 被调用时（或者 `final_suspend` 没有挂起），协程帧会按构造的逆序被销毁：Promise 对象析构 -\> 参数析构 -\> `operator delete` 释放内存。

### 第三部分：Promise 的高级定制能力

Promise 不仅控制生命周期，还能精细地定制协程内部的行为。

#### 1\. 如何选择 Promise 类型？—— `coroutine_traits`

编译器不是凭空知道用哪个 Promise 类型的。它通过一个叫 `std::experimental::coroutine_traits` 的模板来查找。

  * **推导规则**：`coroutine_traits<协程返回类型, 参数类型...>::promise_type`。
  * **默认实现**：默认情况下，`coroutine_traits` 会在**协程的返回类型**中寻找一个名为 `promise_type` 的嵌套类型。例如，`task<T>` 类型的协程，编译器会使用 `task<T>::promise_type`。
  * **定制方法**：如果你想为一个无法修改的类型（如 `std::optional<T>`）实现协程支持，你可以**特化 (specialize)** `coroutine_traits<std::optional<T>, ...>`，在特化版本里指定你自己的 `promise_type`。

#### 2\. 定制 `co_await` 的行为——`await_transform`

Promise 可以通过定义 `await_transform` 方法来“拦截”和“修改”协程内部的每一个 `co_await` 表达式。

`co_await <expr>;` 会被编译器自动转换成 `co_await promise.await_transform(<expr>);`。

这有什么用？

  * **让不可等待的类型变得可等待**：例如，你可以写一个 `await_transform`，让协程能直接 `co_await` 一个 `std::optional`。
  * **禁止等待某些类型**：在生成器（generator）这样的协程中，你可能不希望用户在内部 `co_await` 任何东西，可以把 `await_transform` 删除掉 (`= delete`)。
  * **统一修改等待行为**：比如，你可以实现一个 `await_transform`，让所有的 `co_await` 恢复时都自动切换到指定的线程执行器 (executor) 上。

#### 3\. 定制 `co_yield` 的行为——`yield_value`

`co_yield` 只是一个语法糖。`co_yield <expr>;` 会被编译器自动转换成 `co_await promise.yield_value(<expr>);`。

这意味着，一个协程是否支持 `co_yield`，完全取决于它的 Promise 类型有没有实现 `yield_value` 方法。这通常用于实现生成器（generator），每次 `yield_value` 时挂起协程并产出一个值。

### 总结

这份文档揭示了 C++ 协程设计的核心哲学：**一个高度可定制的框架**。

  * **Promise 对象是协程的“大脑”和“控制器”**，通过一系列标准化的接口方法，精确地定义了协程从创建、启动、返回、异常处理到最终销毁的全部行为。
  * 编译器负责将用户的代码机械地翻译成一个围绕 Promise 方法调用的状态机。
  * 库作者通过编写不同的 Promise 类型，可以创造出功能迥异的协程，如异步任务 (`task`)、生成器 (`generator`)、甚至简化 `optional` 操作的协程等。

理解了 Promise 的工作原理，你就掌握了编写和设计自定义协程类型的钥匙。
