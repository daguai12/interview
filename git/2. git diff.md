好的，我非常乐意为您详细讲解 `git diff` 命令。

`git diff` 是 Git 中一个**极其重要**的命令，它的核心功能是\*\*“比较差异”\*\*。

`git diff` 可以告诉您，在 Git 的不同“区域”或不同“时间点”之间，代码到底发生了什么变化。要完全掌握它，我们必须再次请出 Git 的“三个区域”：

1.  **工作区 (Working Directory)**：您当前正在编辑的文件。
2.  **暂存区 (Staging Area / Index)**：您使用 `git add` 之后，“准备好被提交”的快照。
3.  **仓库 (Repository / HEAD)**：您最后一次 `git commit` 提交的快照。

`git diff` 的不同用法，就是在比较这三个区域中任意两个之间的区别。

-----

### 如何阅读 `git diff` 的输出

在看具体命令前，您必须先学会如何阅读它“天书”一样的输出。

```diff
diff --git a/main.cpp b/main.cpp
index f9e8d7c..a1b2c3d 100644
--- a/main.cpp
+++ b/main.cpp
@@ -1,5 +1,6 @@
 #include <iostream>
 
 int main() {
-    std::cout << "Version 1" << std::endl;
+    std::cout << "Version 2" << std::endl;
+    // Add a new comment
     return 0;
 }
```

**解读：**

  * `diff --git a/main.cpp b/main.cpp`：Git 正在比较两个文件，`a` 版本（旧版）和 `b` 版本（新版）。
  * `--- a/main.cpp`：`-` (减号) 代表“旧版” (`a` 版本) 的文件。
  * `+++ b/main.cpp`：`+` (加号) 代表“新版” (`b` 版本) 的文件。
  * `@@ -1,5 +1,6 @@`：这是“Hunk (代码块)”的头部。
      * `-1,5`：表示这个代码块从旧版（`a`）的**第1行**开始，总共显示**5行**。
      * `+1,6`：表示这个代码块从新版（`b`）的**第1行**开始，总共显示**6行**。
  * **行首的符号 (最关键的)：**
      * `     ` (一个空格)：表示这行**没有变化**（这是上下文）。
      * `-` (减号)：表示这行代码在**旧版中有，新版中没有**（即**被删除**）。
      * `+` (加号)：表示这行代码在**新版中有，旧版中没有**（即**被添加**）。

在上面的例子中，`std::cout << "Version 1" << std::endl;` 这一行被**删除**了，同时**添加**了 `std::cout << "Version 2" << std::endl;` 和 `// Add a new comment` 这两行。

### 场景一：`git diff` (最常用)

**比较对象**：**工作区** vs **暂存区**

**含义**：“显示我**做了哪些修改**，但**还没有 `git add`**？”

**详细案例：**

1.  您有一个 `main.cpp` 文件，内容是 "Version 1"。
2.  您执行 `git add main.cpp`。 (此时 工作区 = 暂存区)
3.  您**再次修改** `main.cpp`，把内容改成 "Version 2"。
4.  此时：
      * 工作区："Version 2"
      * 暂存区："Version 1"
      * `HEAD`："Version 1"
5.  执行 `git diff`：
    ```bash
    $ git diff
    ```
    `git diff` 会比较【工作区 (Version 2)】和【暂存区 (Version 1)】，它会显示：
	
	```diff
    --- a/main.cpp
    +++ b/main.cpp
    @@ -1 +1 @@
    -Version 1
    +Version 2
```

**用途**：这是在您执行 `git add` **之前**，用来检查您所有修改的最佳方式。

-----

### 场景二：`git diff --staged` (或 `--cached`)

**比较对象**：**暂存区** vs **HEAD (最后一次提交)**

**含义**：“显示我**已经 `git add` 了哪些修改**，它们将会被包含在**下一次提交**里？”

**详细案例：**
(接上一个案例)

1.  此时工作区是 "Version 2"，暂存区是 "Version 1"。
2.  您执行 `git diff --staged`：
    ```bash
    $ git diff --staged
    ```
    `git diff --staged` 会比较【暂存区 (Version 1)】和【HEAD (假设也是 Version 1)】。
      * **结果**：**没有任何输出！** 因为您的暂存区和上次提交是一样的。
3.  现在，您执行 `git add main.cpp` (把 "Version 2" 添加到暂存区)。
4.  此时：
      * 工作区："Version 2"
      * 暂存区："Version 2"
      * `HEAD`："Version 1"
5.  再次执行 `git diff --staged`：
    ```bash
    $ git diff --staged
    ```
    `git diff --staged` 会比较【暂存区 (Version 2)】和【HEAD (Version 1)】，它会显示：
```diff
    --- a/main.cpp
    +++ b/main.cpp
    @@ -1 +1 @@
    -Version 1
    +Version 2
```
6.  (此时如果您再执行 `git diff`，将没有任何输出，因为您的工作区和暂存区都是 "Version 2"，内容一致)。

**用途**：这是在您执行 `git commit` **之前**，用来最后确认您将要提交的内容是否正确的最佳方式。

-----

### 场景三：`git diff HEAD`

**比较对象**：**工作区** vs **HEAD (最后一次提交)**

**含义**：“显示我**从上次提交以来，所有的修改**（无论是否 `git add`）？”

**详细案例：**

1.  `HEAD` 是 "Version 1"。
2.  您修改 `main.cpp` 为 "Version 2"，并**执行了 `git add`**。
3.  您**再次修改** `main.cpp` 为 "Version 3"。
4.  此时：
      * 工作区："Version 3"
      * 暂存区："Version 2"
      * `HEAD`："Version 1"
5.  执行 `git diff HEAD`：
    ```bash
    $ git diff HEAD
    ```
    `git diff HEAD` 会比较【工作区 (Version 3)】和【HEAD (Version 1)】，它会显示：
    ```diff
    --- a/main.cpp
    +++ b/main.cpp
    @@ -1 +1 @@
    -Version 1
    +Version 3
    ```
    (它一步到位地显示了最终的差异)

### 场景四：比较两个分支

**比较对象**：**分支 A 的最新提交** vs **分支 B 的最新提交**

**含义**：“显示 `feature` 分支相比 `main` 分支，到底多了哪些修改？”

  * **命令**：`git diff <base-branch>..<target-branch>` (两个点)
  * **常用简化**：`git diff <base-branch> <target-branch>` (一个空格)

**详细案例：**
您想查看 `feature/login` 分支合并到 `main` 分支时，会带来哪些变化。

```bash
$ git diff main..feature/login
```

(或者 `git diff main feature/login`)

**解读**：
这个命令会比较 `main` 分支的“尖端”和 `feature/login` 分支的“尖端”两个快照之间的**所有差异**。

**重要提示（关于 `..` vs `...`）**：

  * `A..B`：显示 B 相对于 A 的**最终差异**。
  * `A...B` (三个点)：显示从 `A` 和 `B` 的**共同祖先**开始，`B` 分支上**独有**的修改。

在发起 Pull Request/Merge Request 之前，`git diff main..feature` (两个点) 是您在本地预览所有变更的最好方法。

-----

### 场景五：比较两个特定的提交

**比较对象**：**任意两个 Commit**

**含义**：“显示从 `commit-A` 到 `commit-B` 之间，到底发生了什么？”

  * **命令**：`git diff <commit-hash-A> <commit-hash-B>`

**详细案例：**
您想查看 `a1b2c3d` 和 `f9e8d7c` 这两次提交之间的区别。

```bash
$ git diff a1b2c3d f9e8d7c
```

**常用技巧：**

  * `git diff HEAD~1 HEAD`：显示**最近一次提交** (`HEAD`) 相比于**它上一次提交** (`HEAD~1`) 做了什么。
  * `git diff HEAD~3 HEAD~1`：显示 `HEAD` 的上一次提交 (`~1`) 相比于 `HEAD` 的上三次提交 (`~3`) 之间的变化。

-----

### 场景六：只看某个文件的差异

您可以在上述**任何命令**的末尾，加上 `-- <file_path>`，来将差异限制在**特定文件**。

**详细案例：**

```bash
# 1. 只看工作区和暂存区之间，main.cpp 的差异
$ git diff -- main.cpp

# 2. 只看暂存区和 HEAD 之间，main.cpp 的差异
$ git diff --staged -- main.cpp

# 3. 只看 main 和 feature 分支之间，utils/helper.cpp 的差异
$ git diff main feature -- utils/helper.cpp
```

(注意：`--` 这个分隔符是好习惯，它告诉 Git 后面的是文件路径，而不是分支名或提交名)

-----

### 总结：`git diff` 速查表

| 您的意图 (我想看...) | 命令 | 比较对象 |
| :--- | :--- | :--- |
| **未暂存**的修改 | `git diff` | 工作区 vs 暂存区 |
| **已暂存** (将要提交) 的修改 | `git diff --staged` | G 暂存区 vs `HEAD` (上次提交) |
| **所有** (未提交) 的修改 | `git diff HEAD` | 工作区 vs `HEAD` (上次提交) |
| 一个**分支**的全部修改 | `git diff main..feature` | `main` 的尖端 vs `feature` 的尖端 |
| **最近一次提交**做了什么 | `git diff HEAD~1 HEAD` | 上次提交 vs 上上次提交 |
| **特定文件**的修改 | `git diff [branch/commit] -- <file>` | [指定区域] 中该文件的差异 |
