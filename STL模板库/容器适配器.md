这是一个非常好的问题。**容器适配器 (Container Adapter)** 是 C++ STL 中一种非常有用的组件，它展示了“组合优于继承”和“封装”的设计思想。

简单来说，容器适配器**不是一个真正的容器**，而是一个\*\*“包装器” (Wrapper)**。它**封装**了一个底层的、常规的 STL 容器（如 `vector`, `list` 或 `deque`），并对外提供一个**受限制的、特定的接口\*\*。

C++ STL 中标准库提供了三种容器适配器：

1.  **`std::stack`** (栈)
2.  **`std::queue`** (队列)
3.  **`std::priority_queue`** (优先队列)

-----

### 1\. 为什么叫“适配器”？

它被称为“适配器”（Adapter）是源于**设计模式**中的**适配器模式**。它的核心作用是：

1.  **修改接口：** 它将一个类（底层容器）的接口，“适配”成客户端（你）所期望的另一个接口。
2.  **限制功能：** 它刻意地**隐藏**了底层容器的绝大部分功能（比如 `operator[]` 随机访问、`insert` 中间插入等）。

例如，`std::stack`（栈）的规则是 **LIFO (后进先出)**。它只允许你在“顶部” `push` 和 `pop`。

你可以用 `std::vector` 来实现一个栈，但如果你直接使用 `vector`，你（或你的同事）可能会不小心调用 `insert(v.begin(), ...)` 从“底部”插入一个元素，这就**破坏了“栈”的规则**。

`std::stack` 通过**封装** `vector`，**只**暴露 `push()` (内部调用 `push_back()`) 和 `pop()` (内部调用 `pop_back()`) 接口，从而在编译期就**保证**了“栈”这个数据结构的逻辑纯洁性。

### 2\. 适配器与容器的根本区别

`std::vector`、`std::list`、`std::map` 这些被称为“一等容器”（First-class Containers）。适配器与它们的最大区别在于：

> **容器适配器不提供迭代器 (Iterators)。**

这意味着：

  * 你**不能**使用 `for (auto& item : my_stack)` 这样
    的 C++11 范围 for 循环来遍历它。
  * 你**不能**将它传递给 `<algorithm>` 中的算法，比如 `std::sort(my_queue.begin(), my_queue.end())`（这根本无法编译）。

适配器被设计为只能通过其特定的成员函数（如 `push`, `pop`, `top`, `front`）进行访问。

### 3\. 三种容器适配器详解

#### 1\. `std::stack` (栈)

  * **概念：** LIFO (Last-In, First-Out / 后进先出)。就像一叠盘子，你总是从最上面放，也从最上面取。
  * **核心接口：**
      * `push(value)`：向栈顶添加一个元素。
      * `pop()`：从栈顶移除一个元素（注意：`pop` **不返回**被移除的元素）。
      * `top()`：返回对栈顶元素的**引用**。
      * `empty()`：检查是否为空。
      * `size()`：返回元素个数。
  * **底层容器：**
      * C++ 声明：`template <class T, class Container = std::deque<T>> class stack;`
      * **默认容器：`std::deque<T>`**。
      * **可选容器：** `std::vector<T>`, `std::list<T>`。
      * **为什么默认是 `deque`？**
          * `stack` 只需要在**尾部**进行 `push_back` 和 `pop_back`。
          * `vector`、`list`、`deque` 都可以 $O(1)$ 完成这些操作。
          * 但 `vector` 在 `capacity` 用尽时，`push_back` 会触发 $O(n)$ 的**重新分配**（移动所有元素），这可能导致性能抖动。
          * `list` 有 $O(1)$ 的插入，但它的内存开销大（每个元素 2 个指针）且缓存极不友好。
          * `deque` (双端队列) 提供了 $O(1)$ 的 `push_back`（均摊，但通常比 `vector` 更平滑，因为它只复制一个指针块），且缓存局部性远好于 `list`。因此 `deque` 是一个最均衡的默认选择。

#### 2\. `std::queue` (队列)

  * **概念：** FIFO (First-In, First-Out / 先进先出)。就像排队买票，先来的人先出去。
  * **核心接口：**
      * `push(value)`：向**队尾**添加一个元素。
      * `pop()`：从**队首**移除一个元素（不返回）。
      * `front()`：返回对**队首**元素的引用。
      * `back()`：返回对**队尾**元素的引用。
      * `empty()` / `size()`。
  * **底层容器：**
      * C++ 声明：`template <class T, class Container = std::deque<T>> class queue;`
      * **默认容器：`std::deque<T>`**。
      * **可选容器：** `std::list<T>`。
      * **为什么默认是 `deque`？**
          * `queue` 需要高效的**尾部插入** (`push_back`) 和**头部删除** (`pop_front`)。
          * `std::vector` **不能**用作 `queue` 的底层容器，因为它的 `pop_front`（即 `erase(v.begin())`）是 $O(n)$ 复杂度，性能极差。
          * `std::list` 可以 $O(1)$ 完成这两个操作，但缓存不友好。
          * `std::deque` 被设计为*专门*用于 $O(1)$ 的 `push_back` 和 $O(1)$ 的 `pop_front`，且缓存性能远好于 `list`。因此 `deque` 是 `queue` 的完美选择。

#### 3\. `std::priority_queue` (优先队列)

这是最特殊的一个适配器。它既不是 LIFO 也不是 FIFO，而是\*\*“最高优先级先出”\*\*。

  * **概念：** 内部是一个**二叉堆 (Binary Heap)** 结构。你 `push` 任何元素，但当你 `top()` 时，你永远看到的是\*\*“最大”\*\*（或“最小”）的那个元素。
  * **核心接口：**
      * `push(value)`：添加一个元素，并 $O(\log n)$ 调整堆。
      * `pop()`：移除**堆顶**（最大/最小）的元素，并 $O(\log n)$ 调整堆。
      * `top()`：返回对**堆顶**（最大/最小）元素的引用（$O(1)$）。
      * `empty()` / `size()`。
  * **底层容器：**
      * C++ 声明：
        ```cpp
        template <class T, 
                  class Container = std::vector<T>, 
                  class Compare = std::less<T> > // 注意第三个参数
        class priority_queue;
        ```
      * **默认容器：`std::vector<T>`**。
      * **可选容器：** `std::deque<T>`。
      * **为什么默认是 `vector`？**
          * 二叉堆（特别是完全二叉树）可以被**完美地**映射到一个**数组 (vector)** 上，通过索引 `i`（父） $\to$ `2i+1`, `2i+2`（子）来导航。
          * 这种方式内存开销最小（没有指针），缓存局部性**极好**。
          * 堆算法（`push_heap`, `pop_heap`）需要 $O(1)$ 的**随机访问**能力，`vector` 和 `deque` 都可以提供。`list` 不能。
          * `vector` 的连续内存比 `deque` 的分块内存在堆操作上略有优势，因此 `vector` 是默认选择。
  * **`Compare` (比较器) —— 最常见的陷阱：**
      * `Compare` 决定了什么是“优先级高”。
      * 默认是 **`std::less<T>`** (小于号)。
      * `std::less` 会构建一个 **Max-Heap (大顶堆)**。即 `a < b` 为 `true` 时，`b` 的优先级更高。所以 `top()` 永远是**最大**的元素。
      * **如何获取小顶堆？** 如果你想要 `top()` 永远是**最小**的元素，你必须手动指定比较器为 **`std::greater<T>`**。
        ```cpp
        // 大顶堆 (默认)
        std::priority_queue<int> max_heap; 

        // 小顶堆 (常用)
        std::priority_queue<int, std::vector<int>, std::greater<int>> min_heap;
        ```

-----

### 总结：概览表

| 适配器 | `std::stack` | `std::queue` | `std::priority_queue` |
| :--- | :--- | :--- | :--- |
| **数据结构** | LIFO (后进先出) | FIFO (先进先出) | 优先级高先出 (堆) |
| **核心操作** | `push`, `pop`, `top` | `push`, `pop`, `front` | `push`, `pop`, `top` |
| **默认底层** | `std::deque<T>` | `std::deque<T>` | `std::vector<T>` |
| **允许底层** | `vector`, `list`, `deque` | `list`, `deque` | `vector`, `deque` |
| **迭代器** | **无** | **无** | **无** |
