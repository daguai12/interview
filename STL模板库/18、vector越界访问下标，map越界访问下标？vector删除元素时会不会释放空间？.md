### 1\. `vector` 越界访问下标

这取决于您*如何*访问它。`vector` 提供了两种访问方式，它们在安全性和行为上完全不同：

#### A. 使用 `operator[]` (例如 `v[10]`)

  * **行为：** **不进行任何边界检查**。
  * **原因：** 为了性能。`vector` 的设计目标之一是提供与 C 风格裸数组（`T[]`）相媲美的速度。C++ 的核心哲学是“你不需要为你不使用的东西付费”。如果你（程序员）能*保证*你的索引是合法的，`vector` 就不会强加额外的 `if` 检查来拖慢你的循环。
  * **后果：** 如果下标越界（即 `index >= v.size()`），将导致**未定义行为 (Undefined Behavior, UB)**。
      * **什么是未定义行为？** 这意味着任何事情都可能发生。程序*可能*立即崩溃（段错误, Segmentation Fault），*也可能*不会崩溃，而是读取或写入了不属于它的内存（例如，它可能读到了 `capacity()` 范围内但 `size()` 范围外的垃圾数据，或者更糟，它写坏了内存中的其他变量），导致程序在未来的某个完全不相关的时刻以诡异的方式崩溃。这是最难调试的 bug 之一。

#### B. 使用 `.at()` (例如 `v.at(10)`)

  * **行为：** **总是进行边界检查**。
  * **原因：** 为了安全。这是 `vector` 提供的“安全”访问方式。
  * **后果：** 如果下标越界（`index >= v.size()`），`.at()` 会立即**抛出一个 `std::out_of_range` 异常**。
      * 你可以使用 `try...catch` 块来捕获这个异常并优雅地处理错误，而不是让程序崩溃。

**总结：** 在性能关键的循环中，且你 100% 确定索引合法时，使用 `[]`。在其他所有你不那么确定的情况下，**优先使用 `.at()` 来保证程序安全**。

### 2\. `map` 越界访问下标

"越界访问"在 `map` 的上下文中通常意味着\*\*“访问一个不存在的键 (Key)”\*\*。

和 `vector` 一样，`map` 也有两种行为不同的访问方式：

#### A. 使用 `operator[]` (例如 `m["key"]`)

  * **行为：** 这是 `map` 最具特色的（也是最容易误用的）功能。它执行\*\*“访问或插入”\*\*操作。
  * **后果：**
    1.  `map` 会首先查找键 `"key"`。
    2.  如果键**存在**，它会返回对该键所关联的 `Value` 的引用（与 `vector` 行为类似）。
    3.  如果键**不存在**：
          * `map` **会立即插入这个新的键 `"key"`**。
          * 与这个新键关联的 `Value` 会被**默认构造**（例如，`int` 会被初始化为 `0`，`string` 会被初始化为 `""`）。
          * 然后，`operator[]` 会返回对这个**新创建的、值为 0 的 `Value`** 的引用。
  * **总结：** `map` 的 `operator[]` **永远不会崩溃或抛出异常**。但它有一个“副作用”，即当你试图“读取”一个不存在的键时，它会**自动向 `map` 中插入一个新元素**。

#### B. 使用 `.at()` (例如 `m.at("key")`)

  * **行为：** 这是 C++11 引入的“安全”访问方式。它**只访问，不插入**。
  * **后果：**
    1.  `map` 查找键 `"key"`。
    2.  如果键**存在**，返回 `Value` 的引用。
    3.  如果键**不存在**，它会立即**抛出一个 `std::out_of_range` 异常**。

**如何安全地检查 `map` 中是否存在某个键？**
如果你不想插入也不想处理异常，正确的方式是使用 `.find()`：

```cpp
auto it = m.find("key");
if (it == m.end()) {
    // "key" 不存在
} else {
    // "key" 存在, 值为 it->second
}
```

### 3\. `vector` 删除元素时会不会释放空间？

不，**几乎所有情况下都不会**。

这又回到了 `size()` 和 `capacity()` 的区别：

  * `size()`：`vector` 中**实际**有多少个元素。
  * `capacity()`：`vector` **总共**分配了多少内存空间。

当你调用 `pop_back()`、`erase()` 或 `clear()` 时：

1.  `vector` 会调用被删除元素的**析构函数**。
2.  `vector` 会将它的 `size()` 减小。
3.  `vector` 的 `capacity()` **保持不变**。

**为什么不释放？**
这是一种**性能优化**。`vector` 假设，如果你刚删除了元素，你很可能马上又要 `push_back` 新的元素。释放内存（`free`/`delete`）和重新分配内存（`new`）是非常昂贵的操作。`vector` 通过保留这块已分配的内存（即保持 `capacity` 不变），可以让你在下次 `push_back` 时享受 $O(1)$ 的速度，避免了不必要的重分配。

#### 如何强制 `vector` 释放空间？

如果你确实需要（比如你刚清空了一个占用 2GB 内存的 `vector`，并希望把内存还给操作系统），你有两种方法：

**1. (C++11及以后) `shrink_to_fit()`**
这是最现代、最清晰的方法。

```cpp
v.clear(); // size 变为 0, capacity 不变
v.shrink_to_fit(); // 请求将 capacity 缩减到 size (即 0)
```

  * `shrink_to_fit()` 是一个“非绑定请求”，意思是 `vector` 的实现*可以*选择忽略它，但在所有主流实现中，它都会触发一次**重新分配**，将 `capacity` 降低到与 `size` 相等。

**2. (C++98/03) "交换技巧" (Swap Trick)**
这是 C++11 之前的标准做法，现在依然 100% 有效。

```cpp
std::vector<int>().swap(v);
```

  * `std::vector<int>()`：创建一个匿名的、空的临时 `vector`（`size=0`, `capacity=0`）。
  * `.swap(v)`：将这个空 `vector` 的内部状态（三个指针）与 `v` 交换。
  * 交换后，`v` 变为 `size=0`, `capacity=0`。
  * 这条语句结束时，那个“临时 `vector`”（它现在持有了 `v` 原来的大内存）被析构，从而**释放了所有内存**。
