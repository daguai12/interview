这是一个非常核心且关键的问题！在 C++ STL 中，“删除一个元素”这个操作，根据你使用的**容器类型**不同，其实现、性能和（最重要的）**迭代器失效**规则也**完全不同**。

我将为你详细分解每种主流容器的删除操作。

-----

### 删除操作的核心三要素

当你考虑删除时，必须同时考虑这三点：

1.  **如何调用？** (API 是什么？按位置删还是按值删？)
2.  **有多快？** (性能复杂度, $O(1)$ 还是 $O(n)$？)
3.  **有何后果？** (**迭代器失效**规则，这最容易导致程序崩溃！)

-----

### 1\. `std::vector` (动态数组)

`vector` 的核心是**连续内存**。这决定了它的删除特性。

  * **内部工作：** 当你删除一个元素时，`vector` **必须**保持其内存连续性。它会将被删除元素*之后*的**所有**元素都向前平移一个位置，以填补空缺。
  * **性能： $O(n)$** (线性复杂度)。
      * 删除第 1 个元素（`v.erase(v.begin())`）是**最坏**情况，需要移动 $n-1$ 个元素。
      * 删除最后 1 个元素（`v.pop_back()`）是**最好**情况，不需要移动任何元素，复杂度为 **$O(1)$**。

#### A. 按位置删除：`erase(iterator)`

```cpp
std.vector<int> v = {10, 20, 30, 40, 50};
auto it = v.begin() + 2; // 指向 30

// 'erase' 会返回一个指向“被删除元素的下一个元素”的新迭代器
// 在这里，它删除了 30，并返回指向 40 的迭代器
it = v.erase(it); 

// v 现在是: {10, 20, 40, 50}
// it 指向: 40
```

  * **迭代器失效：**
      * `erase` 操作会使**被删除点（`pos`）及之后**的所有迭代器、指针和引用**全部失效**。
      * **这是 `vector` 最危险的特性！**

#### B. 按值删除：`std::erase` / `std::erase_if` (C++20)

`vector` 没有内置的 `erase(value)`。在 C++20 之前，我们必须使用 "Erase-Remove Idiom"，非常繁琐。C++20 提供了最好的方法：

```cpp
std.vector<int> v = {1, 2, 3, 2, 4, 2, 5};

// C++20: 删除所有等于 2 的元素
std::erase(v, 2); 
// v 现在是: {1, 3, 4, 5}

// C++20: 删除所有偶数
std::erase_if(v, [](int i){ return i % 2 == 0; });
```

### 2\. `std::list` (双向链表)

`list` 的核心是**节点**（Node），每个节点在内存中不连续，通过 `_prev` 和 `_next` 指针相连。

  * **内部工作：** 删除一个元素，只需要修改其**前一个**节点和**后一个**节点的指针，让它们互相指向对方，然后释放被删除元素的节点内存。
  * **性能： $O(1)$** (常数复杂度)。
      * 无论在 `list` 的哪个位置（头部、中间、尾部）删除，性能都是 $O(1)$。这是 `list` 相比 `vector` 的最大优势。

#### A. 按位置删除：`erase(iterator)`

```cpp
std.list<int> l = {10, 20, 30, 40, 50};
auto it = std::next(l.begin(), 2); // 指向 30

// 'erase' 同样返回下一个元素的迭代器
it = l.erase(it);

// l 现在是: {10, 20, 40, 50}
// it 指向: 40
```

  * **迭代器失效：**
      * `list::erase` **只会**使指向**被删除元素**的迭代器、指针和引用失效。
      * 所有指向**其他**元素的迭代器**全部保持有效**。
      * 这是 `list` 最强大的特性！

#### B. 按值删除：`remove(value)` / `remove_if(predicate)`

`list` 提供了内置的 `remove` 成员函数，它会遍历整个链表并删除所有匹配项。

```cpp
std.list<int> l = {1, 2, 3, 2, 4, 2, 5};
l.remove(2); // l 现在是: {1, 3, 4, 5}

l.remove_if([](int i){ return i % 2 == 0; });
```

  * **性能：** $O(n)$，因为它必须遍历整个列表来查找。

### 3\. `std::map` / `std::set` (红黑树)

`map` 和 `set` 的核心是**平衡二叉搜索树**（红黑树）。

  * **内部工作：** 删除一个元素（节点）后，树可能需要“旋转”和“重新着色”以保持平衡。
  * **性能：** $O(\log n)$ (对数复杂度)。

#### A. 按位置删除：`erase(iterator)`

如果你**已经有**一个指向元素的迭代器（比如通过 `find()` 得到的），用它来删除是最高效的。

```cpp
std.map<int, std::string> m = {{1, "a"}, {2, "b"}, {3, "c"}};
auto it = m.find(2); // O(log n)

if (it != m.end()) {
    // C++11 起，erase(iterator) 性能为均摊 O(1)
    // C++98 中，性能为 O(log n)
    it = m.erase(it); // 'it' 在 C++11 后会指向下一个元素 (key=3)
}
// m 现在是: {{1, "a"}, {3, "c"}}
```

  * **迭代器失效：**
      * 与 `list` 类似，**只会**使指向**被删除元素**的迭代器失效。
      * 所有其他迭代器**保持有效**。（因为树节点不会像 `vector` 一样平移）。

#### B. 按键删除：`erase(key)`

这是最常用的方式。

```cpp
std.map<int, std::string> m = {{1, "a"}, {2, "b"}, {3, "c"}};

// erase(key) 返回被删除元素的“数量” (在 map/set 中只会是 0 或 1)
size_t count = m.erase(2); 

// m 现在是: {{1, "a"}, {3, "c"}}
// count 是: 1
```

  * **性能：** $O(\log n)$。它首先需要 $O(\log n)$ 的时间来查找 `key`，然后再花 $O(\log n)$ 的时间删除和再平衡。

### 4\. `std::unordered_map` / `std::unordered_set` (哈希表)

`unordered_` 系列的核心是**哈希表**。

  * **内部工作：** 通过 `key` 的哈希值找到对应的“桶”，然后在桶（通常是一个链表）中删除该元素。
  * **性能：** **$O(1)$ (平均)**，最坏 $O(n)$。

#### A. 按位置删除：`erase(iterator)`

```cpp
std.unordered_map<int, std::string> m = {{1, "a"}, {2, "b"}, {3, "c"}};
auto it = m.find(2); // O(1) 平均

if (it != m.end()) {
    // 性能为 O(1) 平均
    it = m.erase(it); // 'it' 在 C++11 后会指向桶中的下一个元素
}
```

  * **迭代器失效：**
      * **只会**使指向**被删除元素**的迭代器失效。
      * （*注意：如果删除操作触发了“重哈希”(Rehashing)，理论上所有迭代器都会失效，但这在 `erase` 时极其罕见*）。

#### B. 按键删除：`erase(key)`

```cpp
std::unordered_map<int, std::string> m = {{1, "a"}, {2, "b"}, {3, "c"}};
size_t count = m.erase(2); // O(1) 平均
```

  * **性能：** **$O(1)$ (平均)**。

### 总结：最常见的陷阱 —— 在循环中删除

这是导致程序崩溃的头号元凶。

#### ❌ 错误的代码 (适用于所有容器)

```cpp
for (auto it = v.begin(); it != v.end(); ++it) {
    if (/* 满足删除条件 */) {
        v.erase(it); // 灾难！
        // 1. 'it' 在这里立即失效了。
        // 2. 循环头的 '++it' 将对一个失效的迭代器进行操作。
        // 3. 导致未定义行为 (UB)，程序崩溃。
    }
}
```

#### ✅ 正确的 C++11 统一写法 (适用于所有容器)

`erase` 函数被设计为返回下一个有效迭代器，我们必须用它来更新 `it`。

```cpp
for (auto it = c.begin(); it != c.end(); /* 注意：这里没有 ++it */ ) {
    if (/* 满足删除条件 */) {
        // 关键：用 erase 的返回值覆盖旧的、已失效的 'it'
        it = c.erase(it); 
    } else {
        // 只有在没有删除时，才手动 ++it
        ++it;
    }
}
```

#### ✅ 最好的 C++20 写法 (仅适用于 `vector`, `string`, `deque`, `list`)

```cpp
// 一行代码，安全、高效、易读
std::erase_if(c, [](const auto& element){
    return /* 满足删除条件 */;
});
```

### 概览：容器删除特性对比

| 容器                  | `erase(iterator)` 性能   | `erase(key)` 性能    | 迭代器失效规则 (最重要！)         |
| :------------------ | :--------------------- | :----------------- | :--------------------- |
| `std::vector`       | **$O(n)$**             | (无)                | **被删点及之后**的**所有**迭代器失效 |
| `std::list`         | **$O(1)$**             | (无, 但有 `remove()`) | **仅**被删除的迭代器失效         |
| `std::deque`        | **$O(n)$**             | (无)                | **所有**迭代器失效 (规则最严苛)    |
| `std::map/set`      | 均摊 **$O(1)$** (C++11+) | **$O(\log n)$**    | **仅**被删除的迭代器失效         |
| `unordered_map/set` | 平均 **$O(1)$**          | 平均 **$O(1)$**      | **仅**被删除的迭代器失效         |
