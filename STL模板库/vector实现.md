`std::vector` 是 C++ STL 中使用最广泛的容器，它本质上是一个\*\*“动态数组”（Dynamic Array）\*\*。

它封装了一个 C 风格的裸数组（`T*`），并提供了自动内存管理（自动增长和收缩）的能力，同时保证了元素的**连续存储**。

下面我们来详细讲解它的内部实现。

-----

### 1\. 核心数据结构：三个指针

在几乎所有主流的 STL 实现中（如 libstdc++, libc++, MSVC STL），一个 `vector` 对象（在栈上）的大小都是固定的，它只包含**三个指针**（或者等价的“指针和计数器”）。

这三个指针指向\*\*堆（Heap）\*\*上分配的内存块：

```cpp
template <class T, class Allocator = std::allocator<T>>
class vector {
protected:
    T* _begin;            // 指向已分配内存块的“起始”
    T* _end;              // 指向最后一个“已构造元素”的“下一个”位置
    T* _end_of_storage; // 指向已分配内存块的“末尾”的“下一个”位置
};
```

#### 图解这三个指针：

想象一个 `vector<int>`，它分配了 6 个 `int` 的空间，但只存储了 4 个元素：

```
         [ 10 | 20 | 30 | 40 |  ?  |  ?  ]
           ^              ^         ^
           |              |         |
         _begin          _end     _end_of_storage
```

  * `_begin`：指向 `10`。
  * `_end`：指向 `40` 之后的那个未初始化内存 `?`。
  * `_end_of_storage`：指向最后一个 `?` 之后的内存地址。

-----

### 2\. 关键概念：`size()` vs `capacity()`

这三个指针直接导出了 `vector` 两个最重要的属性：

1.  **`size()`（大小）**

      * `vector` 中**实际存储**了多少个元素。
      * **实现：** `return _end - _begin;`
      * 在上图中，`size()` 是 4。

2.  **`capacity()`（容量）**

      * `vector` **总共分配**了多少内存空间（即在*不*重新分配内存的情况下，最多能装多少个元素）。
      * **实现：** `return _end_of_storage - _begin;`
      * 在上图中，`capacity()` 是 6。

> **核心关系：** `0 <= size() <= capacity()` 始终成立。

-----

### 3\. 最重要的操作：`push_back(const T& value)`

`push_back` 是 `vector` 最核心的操作，也是理解其动态增长的关键。

#### 情况一：快速路径（`size() < capacity()`）

当 `vector` 还有剩余容量时，`push_back` 非常快。

```cpp
void push_back(const T& value) {
    if (_end != _end_of_storage) {
        // 1. 在 _end 指向的内存位置上，使用“定位new”(placement new)
        //    来构造新元素（调用 T 的拷贝构造函数）。
        allocator.construct(_end, value); 
        
        // 2. 将 _end 指针后移一位。
        ++_end; 
    } else {
        // 3. 容量不足，进入情况二：重新分配
        _reallocate_and_insert(value); 
    }
}
```

  * **复杂度：** $O(1)$ （常数时间）。

#### 情况二：重新分配（`size() == capacity()`）

当容量用尽时，`vector` 必须“长大”。这是一个昂贵的操作：

1.  **计算新容量：** `vector` 会申请一个比当前容量**更大**的新内存块。

      * **增长因子 (Growth Factor)：** 新容量通常是旧容量的 `2` 倍（在 GCC/Clang 中）或 `1.5` 倍（在 MSVC 中）。`new_capacity = old_capacity * 2;`
      * 这个“倍增”策略是实现**均摊 $O(1)$** 复杂度的关键。

2.  **分配新内存：** 使用分配器（`Allocator`）在堆上申请 `new_capacity * sizeof(T)` 大小的新内存块。

3.  **迁移元素：**

      * `vector` 会遍历旧内存块中的所有（`size()` 个）元素，并将它们\*\*移动（move）\*\*到新内存块中。
      * **（重要细节）** 它会优先使用 `T` 的**移动构造函数 (Move Constructor)**。如果 `T` 没有移动构造函数，或者移动构造函数*没有*被标记为 `noexcept`（见下文“异常安全”），它会降级使用**拷贝构造函数 (Copy Constructor)**。

4.  **构造新元素：** 在新内存块的末尾（新的 `_end` 位置）构造 `push_back` 传入的那个 `value`。

5.  **释放旧内存：** 销毁（调用析构函数）旧内存块中的所有元素，并释放旧内存块。

6.  **更新指针：** 将 `_begin`, `_end`, `_end_of_storage` 更新为指向新内存块的相应位置。

<!-- end list -->

  * **复杂度：** $O(n)$ （线性时间），因为需要移动所有 $n$ 个旧元素。

-----

### 4\. 为什么 `push_back` 是“均摊 $O(1)$”？

`push_back` 在最坏情况下是 $O(n)$，但为什么我们说它的“均摊复杂度”（Amortized Complexity）是 $O(1)$？

假设增长因子是 2，我们从一个空 `vector` 开始连续 `push_back` 17 个元素：

  * `push_back` 1：`cap=0` -\> `cap=1`。（分配 1，移动 0）
  * `push_back` 2：`cap=1` -\> `cap=2`。（分配 2，移动 1）
  * `push_back` 3：`cap=2` -\> `cap=4`。（分配 4，移动 2）
  * `push_back` 4：`cap=4`。（$O(1)$）
  * `push_back` 5：`cap=4` -\> `cap=8`。（分配 8，移动 4）
  * ...
  * `push_back` 9：`cap=8` -\> `cap=16`。（分配 16，移动 8）
  * ...
  * `push_back` 17：`cap=16` -\> `cap=32`。（分配 32，移动 16）

当你插入 $N$ 个元素时，总的移动（或拷贝）次数大约是 $1 + 2 + 4 + 8 + ... + N/2$，这是一个等比数列，总和约等于 $N$。

  * **总成本：** 插入 $N$ 个元素，总共执行了约 $N$ 次移动操作（$O(N)$）和 $N$ 次构造操作（$O(N)$）。
  * **均摊成本：** `总成本 / 总操作次数 = O(N) / N = O(1)`。

平均下来，每次 `push_back` 操作的成本是一个常数。

### 5\. 其他操作的实现

#### `pop_back()`

1.  将 `_end` 指针前移一位。
2.  调用 `_end` 现在指向的那个元素（即刚刚被“弹出”的元素）的析构函数 `~T()`。
3.  （`vector` *不会* 缩小容量，内存仍然被保留）。

<!-- end list -->

  * **复杂度：** $O(1)$。

#### `operator[index]`

1.  直接返回 `_begin[index]` 的引用。
2.  **不进行边界检查**。如果 `index >= size()`，这是未定义行为（Undefined Behavior）。

<!-- end list -->

  * **复杂度：** $O(1)$。（这就是 `vector` 媲美裸数组的性能来源）。

#### `at(index)`

1.  检查 `index < size()`。
2.  如果检查失败，抛出 `std::out_of_range` 异常。
3.  如果检查成功，返回 `_begin[index]` 的引用。

<!-- end list -->

  * **复杂度：** $O(1)$。

#### `insert(pos, value)`

在 `vector` 中部插入元素是**非常昂贵**的：

1.  首先，检查是否需要重新分配（`size == capacity`），如果需要，则执行上述的 $O(n)$ 重新分配流程。
2.  假设容量足够。
3.  将从 `pos` 位置到 `_end` 位置的所有元素，向右\*\*移动（或拷贝）\*\*一个位置，为新元素腾出空间。
4.  在 `pos` 位置构造新元素 `value`。

<!-- end list -->

  * **复杂度：** $O(n)$。因为平均需要移动 `n / 2` 个元素。

#### `erase(pos)`

在 `vector` 中部删除元素也是**非常昂贵**的：

1.  调用 `pos` 位置元素的析构函数 `~T()`。
2.  将从 `pos + 1` 位置到 `_end` 位置的所有元素，向左\*\*移动（或拷贝）\*\*一个位置，填补被删除的空缺。
3.  将 `_end` 指针前移一位。

<!-- end list -->

  * **复杂度：** $O(n)$。

### 6\. 内存与异常安全（重要）

#### A. 连续内存保证

`std::vector` **保证**其元素在内存中是**连续存储 (Contiguous Storage)** 的。

  * 这意味着，如果 `v` 是一个 `vector<int>` 且不为空，那么 `&v[0]` 是一个合法的 `int*` 指针。
  * 你可以将 `&v[0]` 传递给任何期望 C 风格数组（如 `int*`）的 C API，例如 `read(fd, &v[0], v.size() * sizeof(int))`。
  * `v[i]` 和 `*(v._begin + i)` 是等价的。

#### B. 迭代器失效 (Iterator Invalidation)

这是 `vector` 最容易出错的地方：

1.  **`push_back` (有重分配时)：** 当 `push_back` 触发重新分配（`size == capacity`）时，**所有**指向该 `vector` 的迭代器、指针和引用都会**全部失效**。因为它们指向的旧内存已经被 `delete` 了。
2.  **`push_back` (无重分配时)：** 只有 `end()` 迭代器会失效。指向已存在元素的迭代器、指针和引用仍然有效。
3.  **`insert`：** \* 如果发生重分配，所有迭代器失效。
      * 如果未发生重分配，**插入点（`pos`）及之后**的所有迭代器、指针和引用都会失效（因为它们被向右移动了）。
4.  **`erase`：** \* **删除点（`pos`）及之后**的所有迭代器、指针和引用都会失效（因为它们被向左移动了，或者 `_end` 变了）。

#### C. 强异常保证 (Strong Exception Guarantee)

`vector` 在（C++11后）努力提供强异常保证，尤其是在 `push_back` 重分配时：

  * **问题：** 假设在重分配时，我们正在把 10 个元素从旧内存“移动”到新内存。当移动到第 5 个元素时，`T` 的**移动构造函数**抛出了一个异常。会发生什么？

      * 新内存块上有 5 个新元素。
      * 旧内存块上有 10 个（可能已被“掏空”的）元素。
      * `vector` 处于一种被破坏的、不一致的状态！

  * **解决方案：** `std::move_if_noexcept`

      * `vector` 在重分配时会检查 `T` 的移动构造函数是否被标记为 `noexcept`（即保证不抛出异常）。
      * **如果 `noexcept(true)`：** `vector` 会安全地使用移动构造函数（很快）。
      * **如果 `noexcept(false)`（或没有移动构造函数）：** `vector` 会**强制使用拷贝构造函数**来迁移元素。
      * **为什么用拷贝？** 如果在拷贝第 5 个元素时抛出异常，`vector` 会捕获该异常，释放掉*新*分配的内存，然后*原封不动地返回*。`vector` 自身的状态没有改变（仍然指向旧内存块，包含 10 个完好的元素），就好像 `push_back` 操作从未发生过一样。这就是**强异常保证**。

### 总结

`std::vector` 是一个精密设计的封装：

  * **内部：** 三个指针（`_begin`, `_end`, `_end_of_storage`）。
  * **优点：**
      * $O(1)$ 的随机访问（`operator[]`）。
      * $O(1)$（均摊）的尾部添加（`push_back`）。
      * $O(1)$ 的尾部删除（`pop_back`）。
      * 100% 连续内存，与 C API 兼容性好，缓存局部性极佳。
  * **缺点：**
      * $O(n)$ 的中部插入/删除（`insert`, `erase`）。
      * `push_back` 可能导致 $O(n)$ 的重分配延迟和迭代器失效。

-----

`vector` 的设计牺牲了中部操作的性能，换取了极致的访问性能和高效的尾部操作。
