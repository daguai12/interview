这是一个非常常见且重要的问题！

很多 C++ 开发者（尤其是初学者）会惊讶地发现，当他们调用 `pop_back()`、`erase()` 甚至 `clear()` 时，`std::vector` 的内存**并没有被释放**。

-----

### 1\. 核心问题：`size()` vs `capacity()`

要理解这一点，你必须先区分 `vector` 的两个关键属性：

  * **`size()` (大小):** `vector` 中**实际存储**了多少个元素。
  * **`capacity()` (容量):** `vector` **总共分配**了多少内存（即在*不*重新分配内存的情况下，最多能装多少个元素）。

**关键点：** `vector` 的设计哲学是“为未来的增长预留空间”。

当你从 `vector` 中删除元素时：

  * `pop_back()`：将 `size()` 减 1，并调用最后一个元素的析构函数。
  * `erase()`：将 `size()` 减少，并调用被删除元素的析构函数，然后平移后续元素。
  * `clear()`：将 `size()` 设为 0，并调用**所有**元素的析构函数。

在上述所有操作中，`capacity()` **保持不变**。`vector` 仍然持有那块（现在是空的）内存，因为它“认为”你可能马上又要 `push_back` 新元素，它想帮你避免昂贵的重新分配。

**示例：**

```cpp
std::vector<int> v;
v.reserve(1000);   // 分配1000个int的容量
for (int i = 0; i < 100; ++i) {
    v.push_back(i); // 填充100个元素
}
// 此时: v.size() == 100, v.capacity() == 1000

v.clear(); // 清空所有元素
// 此时: v.size() == 0, v.capacity() == 1000
// 内存并没有释放！
```

那么，如何**强制** `vector` 释放这些未使用的内存，让 `capacity()` 降回到 `size()` 呢？

-----

### 2\. 释放空间的方法

你有两种主要的方法，一种是现代 C++ (C++11 及以后) 的方式，一种是经典 C++ (C++98/03) 的方式。

#### 方法一 (现代 C++11)：`shrink_to_fit()`

C++11 引入了一个专门为此设计的成员函数：`shrink_to_fit()`。

它是一个“请求”，请求 `vector` 将其 `capacity()` 减少到与 `size()` 相同。

```cpp
std::vector<int> v;
v.reserve(1000);
for (int i = 0; i < 100; ++i) v.push_back(i);

// 此时: v.size() == 100, v.capacity() == 1000
std::cout << "Before: size=" << v.size() << " capacity=" << v.capacity() << std::endl;

// 释放多余的内存
v.shrink_to_fit(); 

// 此时: v.size() == 100, v.capacity() == 100
std::cout << "After:  size=" << v.size() << " capacity=" << v.capacity() << std::endl;
```

**工作原理：**
`shrink_to_fit()` 通常会（但不保证 100%）执行一次新的内存分配：

1.  分配一块大小刚好为 `v.size()` 的新内存。
2.  将所有元素从旧内存**移动**到新内存。
3.  **释放**旧的、巨大的内存块。

> **注意：**
>
> 1.  **非强制性：** C++ 标准规定 `shrink_to_fit()` 只是一个“非绑定请求”(non-binding request)。实现库*可以*选择忽略它。但在所有主流实现（GCC, Clang, MSVC）中，它都会如你所愿地工作。
> 2.  **迭代器失效：** 这是一个**重新分配**操作。因此，**所有**指向该 `vector` 的迭代器、指针和引用都会**全部失效**。
> 3.  **时间复杂度：** $O(n)$，因为它需要移动所有元素。

-----

#### 方法二 (经典 C++98/03)："交换技巧" (Swap Trick)

在 C++11 出现之前，`shrink_to_fit()` 并不存在。开发者们使用了一种非常巧妙的技巧（现在仍然 100% 有效且有保证）来释放内存，称为“交换技巧”。

这个技巧的核心是利用**临时 `vector` 对象的析构**。

**场景 A：你想缩小 `capacity` 使其等于 `size`**

```cpp
std::vector<int> v;
v.reserve(1000);
for (int i = 0; i < 100; ++i) v.push_back(i);

// 此时: v.size() == 100, v.capacity() == 1000

// 经典 C++98/03 "Swap Trick"
std::vector<int>(v).swap(v);

// 此时: v.size() == 100, v.capacity() == 100
```

**逐行解释 `std::vector<int>(v).swap(v);`：**

1.  **`std::vector<int>(v)`**：
      * 这会创建一个**匿名的临时 `vector` 对象**。
      * 这个临时对象是通过 `v` 的**拷贝构造函数**创建的。
      * 关键在于：拷贝构造函数**只会分配刚好足够的空间**来容纳被拷贝的元素。
      * 所以，这个临时 `vector` 的 `size()` 是 100，`capacity()` 也是 100。
2.  **`.swap(v)`**：
      * 这个临时对象立即调用 `swap()` 成员函数，与 `v` 交换其内部状态（即交换 `_begin`, `_end`, `_end_of_storage` 三个指针）。
      * 交换后：
          * `v`：获得了临时对象的内部指针，`size=100`, `capacity=100`。（**目的达成！**）
          * 临时对象：获得了 `v` 的旧内部指针，`size=100`, `capacity=1000`。
3.  **`;` (语句结束)**：
      * 这个**临时对象**在语句结束时被销毁。
      * 它的析构函数被调用，**释放了它所持有的内存**（也就是 `v` 原来的那块 1000 容量的旧内存）。

**场景 B：你想清空 `vector` 并释放所有内存 (size=0, capacity=0)**

如果你调用 `v.clear()`，`size` 变为 0，但 `capacity` 不变。要真正释放所有内存：

```cpp
// 假设 v.size() == 100, v.capacity() == 1000

// C++98/03 Swap Trick 来清空所有
std::vector<int>().swap(v);

// 此时: v.size() == 0, v.capacity() == 0
```

**解释：**

  * `std::vector<int>()`：创建一个默认构造的、完全为空的临时 `vector`（`size=0`, `capacity=0`）。
  * `.swap(v)`：`v` 获得了临时对象的空状态，临时对象获得了 `v` 的旧内存。
  * 临时对象被销毁，释放旧内存。

-----

### 3\. 总结与建议

| 操作 | 目标 | `size()` 变化 | `capacity()` 变化 | 如何释放内存？ |
| :--- | :--- | :--- | :--- | :--- |
| `v.pop_back()` | 删除末尾元素 | `size--` | **不变** | 不释放 |
| `v.erase(it)` | 删除中间元素 | `size--` | **不变** | 不释放 |
| `v.clear()` | 清空所有元素 | 变为 0 | **不变** | 不释放 |
| `v.shrink_to_fit()` | 缩减容量至 `size` | 不变 | **变为 `size`** | **是 (C++11+)** |
| `std::vector<T>(v).swap(v)` | 缩减容量至 `size` | 不变 | **变为 `size`** | **是 (C++98)** |
| `std::vector<T>().swap(v)` | 缩减容量至 0 | 变为 0 | **变为 0** | **是 (C++98)** |

#### 现代 C++ (C++11 及以后) 建议：

  * **99% 的情况：什么都不做。** `vector` 的内存预留是其性能的关键。除非你确定一个 `vector` 在其剩余生命周期内**绝对不会**再增长，否则不要手动缩减它。
  * **1% 的情况：使用 `v.shrink_to_fit()`。** 当你有一个非常大的 `vector`，并且你刚刚清空（或大幅减少）了它的内容，并且你知道它在接下来很长一段时间内都不会再使用（或者你面临极大的内存压力），那么调用 `shrink_to_fit()` 是最清晰、最现代的做法。
