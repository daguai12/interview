`std::deque`（Double-Ended Queue，双端队列）是 C++ STL 中一个非常精巧的容器。它的实现**试图“取 `std::vector` 和 `std::list` 两者之长”**。

  * 它希望拥有 `vector` 那样的 **$O(1)$ 随机访问 `[]`** 和**缓存友好性**。
  * 它希望拥有 `list` 那样的 **$O(1)$ 头部插入/删除 (`push_front`/`pop_front`)**。

`vector` 无法 $O(1)$ `push_front`，而 `list` 无法 $O(1)$ `operator[]`。`deque` 为了同时实现这两个目标，采用了\*\*“分块数组”**或**“块指针映射”\*\*的底层数据结构。

-----

### 1\. 核心数据结构：两级指针结构

`std::deque` 的内部结构**不是**一块连续的内存（不像 `vector`），而是一种两级结构：

1.  **Level 1：中控器 (The Map / Block Pointer Array)**

      * 这是一个**动态数组**（其本身实现类似于 `vector`），但它**不直接存储数据**。
      * 它存储的是**指向“数据块”的指针**。
      * 这个数组就是 `deque` 的“中控器”或“索引”。

2.  **Level 2：数据块 (The Blocks / Chunks)**

      * 这些是**固定大小**（例如 4KB 或 512 个 `T` 元素）的**连续内存块**。
      * 真正的数据元素 `T` 被存储在这些块中。

#### 概念图

一个 `deque` 在内存中的布局看起来像这样：

### 2\. `deque` 的动态行为：环形缓冲区思想

`deque` 的精髓在于，它把**中控器 (Map Array)** 当作一个**环形缓冲区 (Ring Buffer)** 来使用。

`deque` 内部并不总是从“中控器”的 `index = 0` 开始使用，而是从**中间**开始。

```
       [ 中控器 (Map Array) ]
+----------+
| nullptr  |
+----------+
| nullptr  |
+----------+
| Block_A* |  <-- 逻辑上的 "begin()" 可能在这里
+----------+
| Block_B* |
+----------+
| Block_C* |  <-- 逻辑上的 "end()" 可能在这里
+----------+
| nullptr  |
+----------+
| nullptr  |
+----------+
```

  * `deque` 内部有两个关键的迭代器（或指针）`_start` 和 `_finish`。
  * `_start`：指向**第一个元素**（例如 `Block_A` 中的某个位置）。
  * `_finish`：指向**最后一个元素**的**下一个**位置（例如 `Block_C` 中的某个位置）。

#### A. `push_back(value)` (尾部插入) - $O(1)$ 均摊

1.  `_finish` 迭代器（指向队尾）检查它所在的**当前数据块**是否已满。
2.  **情况 1 (最快)：** `_finish` 所在的块**未满**。
      * 直接在 `_finish` 指针处构造 `value`。
      * `_finish` 指针加 1。
      * 复杂度：**$O(1)$**。
3.  **情况 2 (较快)：** `_finish` 所在的块**已满**。
      * `deque` 检查“中控器”数组的**末尾**是否还有空间。
      * 如果有，它会 `new` 一个**新的数据块 (Block\_D)**。
      * 将这个新块的指针放入“中控器”数组的下一个槽位。
      * `_finish` 更新为指向 `Block_D` 的开头。
      * 在 `Block_D` 的开头构造 `value`。
      * 复杂度：**$O(1)$** (加一次堆分配)。
4.  **情况 3 (最慢)：** “中控器”数组本身**也满了**。
      * `deque` 必须**重新分配**一个新的、更大的“中控器”数组。
      * 它将旧中控器中的**指针** `copy`（或 `move`）到新中控器的**中间**（为两端增长预留空间）。
      * **注意：它只拷贝指针，不移动数据！**
      * 释放旧中控器数组。
      * 然后回到情况 2。
      * 复杂度：**均摊 $O(1)$**（与 `vector` 重分配的均摊 $O(1)$ 原理相同）。

#### B. `push_front(value)` (头部插入) - $O(1)$ 均摊

这与 `push_back` 完全对称，只是方向相反。

1.  `_start` 迭代器（指向队首）检查它所在的**当前数据块**的**开头**是否还有空间（即它是否指向 `block_begin`）。
2.  **情况 1 (最快)：** `_start` 所在的块**开头未满**。
      * `_start` 指针减 1。
      * 在新的 `_start` 指针处构造 `value`。
      * 复杂度：**$O(1)$**。
3.  **情况 2 (较快)：** `_start` 所在的块**开头已满**。
      * `deque` 检查“中控器”数组的**开头**是否还有空间。
      * 如果有，它会 `new` 一个**新的数据块 (Block\_Z)**。
      * 将这个新块的指针放入“中控器”数组在 `_start` 之前的槽位。
      * `_start` 更新为指向 `Block_Z` 的末尾。
      * 在 `Block_Z` 的末尾构造 `value`。
      * 复杂度：**$O(1)$** (加一次堆分配)。
4.  **情况 3 (最慢)：** “中控器”数组的**开头也满了**。
      * 触发“中控器”重分配（同上，均摊 $O(1)$）。

### 3\. `operator[]` (随机访问) - $O(1)$

这是 `deque` 的另一个魔法。它如何实现 $O(1)$ 的随机访问？

当你调用 `dq[i]` 时，`deque` 会执行一个（非常快）的**两步计算**：

1.  **计算“块索引” (Block Index)：**

      * `deque` 知道 `_start` 迭代器指向的元素在哪个块 ( `start_block` )、哪个位置 ( `start_offset` )。
      * 它计算 `total_offset = i + start_offset`。
      * `block_index = (total_offset / BLOCK_SIZE) + start_block`
      * 这一定位到了 `dq[i]` 应该在“中控器”的哪个槽位。

2.  **计算“块内索引” (Intra-block Index)：**

      * `element_index = total_offset % BLOCK_SIZE`
      * 这一定位到了 `dq[i]` 在该数据块中的具体位置。

3.  **访问：**

      * `return map[block_index][element_index];`

**这一整套计算只涉及整数的加法、除法和取模，其复杂度是 $O(1)$。**

### 4\. `deque` 的迭代器 (Iterator)

`deque` 的迭代器实现**非常复杂**。

  * `vector::iterator` 内部**只有一个 `T*` 裸指针**。
  * `list::iterator` 内部**只有一个 `Node*` 节点指针**。
  * `deque::iterator` 内部必须**至少包含 4 个指针**：
    ```cpp
    class deque_iterator {
        T* _current;       // 指向当前块中的当前元素
        T* _first;         // 指向当前块的“开始”
        T* _last;          // 指向当前块的“末尾+1”
        T** _map_node;     // 指向“中控器”中，指向当前块的那个“槽位”
    };
    ```

**`deque::iterator::operator++()` (递增) 的伪代码：**

```cpp
iterator& operator++() {
    ++_current; // 1. 移动指向元素的指针
    
    // 2. 检查是否跨越了数据块的边界
    if (_current == _last) {
        // 3. 跨越了！需要跳转到下一个块
        ++_map_node; // 4. 中控器指向下一个槽位
        
        // 5. 更新迭代器，使其指向新块的开头
        _first = *_map_node; 
        _last = _first + BLOCK_SIZE;
        _current = _first;
    }
    return *this;
}
```

这个 `if` 检查，就是 `deque` 迭代器性能**不如 `vector` 迭代器**的根本原因。`vector` 的 `++` 只是一个 `ptr++`，而 `deque` 的 `++` 还需要一次 `if` 比较。

-----

### 5\. 迭代器失效 (Iterator Invalidation)

`deque` 的失效规则是三者中最复杂的：

  * **`push_back` / `push_front`：**

      * **如果“中控器”未重分配**：**所有**迭代器保持有效。**所有**指向元素的指针和引用也**保持有效**。（**这是 `deque` 优于 `vector` 的巨大亮点！**）
      * **如果“中控器”重分配**：**所有**迭代器都会**失效**。但是，指向**元素**的**指针和引用**仍然**保持有效**！（因为数据块本身没有被移动，只是中控器换了地方）。

  * **`insert(pos, ...)` (在中间插入)：**

      * **全部失效！** `insert` 会导致该点之后的所有元素平移。
      * 如果插入点在 `deque` 的前半部分，它会向前平移前面的元素（可能触发 `push_front` 逻辑）。
      * 如果插入点在后半部分，它会向后平移后面的元素（可能触发 `push_back` 逻辑）。
      * 在任何情况下，`insert` 都会导致**所有**迭代器、指针和引用**全部失效**。**这是 `deque` 相比 `vector` 和 `list` 最差的地方**。

  * **`erase(pos)` (在中间删除)：**

      * **全部失效！** 与 `insert` 同理，`erase` 也会平移元素，导致**所有**迭代器、指针和引用**全部失效**。

-----

### 总结：`deque` 的优缺点

| 特性                          | `std::vector`       | `std::deque`               | `std::list`     |
| :-------------------------- | :------------------ | :------------------------- | :-------------- |
| **`operator[]`**            | **$O(1)$ (最快)**     | **$O(1)$ (较快)**            | $O(n)$          |
| **`push_back`**             | $O(1)$ (均摊)         | $O(1)$ (均摊)                | **$O(1)$ (保证)** |
| **`push_front`**            | $O(n)$              | $O(1)$ (均摊)                | **$O(1)$ (保证)** |
| **`insert/erase` (中部)**     | $O(n)$              | $O(n)$                     | **$O(1)$ (保证)** |
| **缓存局部性**                   | **极好** (连续内存)       | **良好** (分块连续)              | 极差 (指针跳转)       |
| **迭代器失效 (push/pop)**        | `push_back` 时可能全部失效 | **最优** (通常只失效 `begin/end`) | **最优** (不失效)    |
| **迭代器失效 (中部 insert/erase)** | `pos` 及之后失效         | **最差** (全部失效)              | **最优** (只失效自己)  |

**何时使用 `std::deque`？**

1.  当你**同时**需要 $O(1)$ 头部插入/删除 和 $O(1)$ 随机访问时。
2.  当你需要一个 `queue` (队列) 时（`std::queue` 默认就使用 `deque`）。
3.  当你需要 `vector` 的功能，但又**不能接受 `push_back` 时迭代器/引用失效**（例如，`vector` 中存的对象互相持有指针）时。

在绝大多数情况下，**`std::vector` 仍然是默认的首选容器**，因为它简单且缓存性能最好。

### 1\. 案例设定

假设我们的 `std::deque` 内部有如下状态：

  * **常量：**

      * `BLOCK_SIZE = 4` (为简单起见，我们假设每个数据块**只能**存放 4 个元素)

  * **中控器 (Map Array)：**

      * `deque` 内部有一个中控器（指针数组），我们假设它有 8 个槽位。
      * `deque` 从中间开始使用，`Block_A` 存放在 `Map[2]`。

    <!-- end list -->

    ```
           [ 中控器 (Map Array) ]
    Index
    [0] -> nullptr
    [1] -> nullptr
    [2] -> [ptr_to_Block_A]
    [3] -> [ptr_to_Block_B]
    [4] -> [ptr_to_Block_C]
    [5] -> nullptr
    [6] -> nullptr
    [7] -> nullptr
    ```

  * **数据块 (Blocks)：**

      * `Block_A`: `[ - | - | 10 | 20 ]`
      * `Block_B`: `[ 30 | 40 | 50 | 60 ]`
      * `Block_C`: `[ 70 | 80 | - | - ]`
        ( `-` 表示未初始化或未使用的内存)

  * **逻辑视图 (Deque)：**

      * `deque` 逻辑上存储的元素是：`[10, 20, 30, 40, 50, 60, 70, 80]`
      * `deque.size()` 是 8。

### 2\. `deque` 的内部已知状态

`deque` 对象**在计算开始前**，*知道*其 `_start` 迭代器的信息：

  * **`start_block` (起始块索引):**

      * 第一个元素 `10` 位于 `Block_A`。
      * `Block_A` 的指针位于中控器的 `Index = 2`。
      * **`start_block = 2`**

  * **`start_offset` (起始块内偏移):**

      * 第一个元素 `10` 位于 `Block_A` 的第 2 个槽位 (索引从0开始)。
      * **`start_offset = 2`**

-----

### 3\. 计算目标：`dq[5]`

现在，我们（用户）请求访问 `deque` 的第 5 号元素（索引从 0 开始）：
`dq[5]`

我们期望得到的值是 `60`。
让我们看看 `deque` 是如何通过计算得到它的。

  * **输入：`i = 5`**

-----

### 4\. 计算过程

#### A. 计算 `total_offset` (总偏移)

`total_offset = i + start_offset`
`total_offset = 5 + 2`
`total_offset = 7`

> **(解释：)** 这个 `7` 的含义是：我们寻找的元素 `dq[5]`，是位于 `start_block`（即 `Block_A`）的**物理起始地址**之后的第 7 个逻辑槽位。

#### B. 计算“块索引” (Block Index)

`block_index = (total_offset / BLOCK_SIZE) + start_block`
`block_index = (7 / 4) + 2`
`block_index = 1 + 2` (这里是整数除法，7/4 = 1)
`block_index = 3`

> **(解释：)** `block_index = 3` 告诉 `deque`，要找的元素位于**中控器 `Map[3]`** 所指向的数据块中。
>
> (检查我们的设定：`Map[3]` 指向 `Block_B`。`dq[5]` (即 60) 确实在 `Block_B` 中。计算正确！)

#### C. 计算“块内索引” (Intra-block Index)

`element_index = total_offset % BLOCK_SIZE`
`element_index = 7 % 4` (7 除以 4 的余数)
`element_index = 3`

> **(解释：)** `element_index = 3` 告诉 `deque`，要找的元素位于目标数据块的第 3 号槽位。

#### D. 最终访问

`deque` 现在执行最终的访问：
`return map[block_index][element_index];`

替换我们计算出的值：
`return map[3][3];`

  * **`map[3]`** $\to$ 访问中控器，得到 `ptr_to_Block_B`。
  * **`[3]`** $\to$ 访问 `Block_B` 的第 3 号槽位。

`Block_B` 是 `[30, 40, 50, 60]`。
`Block_B[3]` 就是 `60`。

计算完成，`deque` 正确返回了 `60`。
